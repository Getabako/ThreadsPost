# Threads Post（アシュラ秘奥義）

Codex（ChatGPT サブスク・**GPT-6.1 Sol**）が、Threads の投稿の**下書き**（本文・トピックタグ・自分への返信・画像）を作るローカルツール。

- **今の段階: 下書きまで**（第一段階の前半）。Threads への投稿は、公式 Threads API で第一段階の後半に対応する
- 有料の API キーは使わない。文章も画像（image_gen）も Codex サブスクで作る
- 計画書: `../plans/20261002-threads-post-phase1.md`

## 使い方（画面）

```bash
cd ThreadsPost
bash ashura-start.sh          # 初回は部品の導入とビルドで数分。ブラウザが開く（http://127.0.0.1:4593）
bash ashura-start.sh stop     # 止める
```

1. **基本情報**: テーマ・誰に・トーン・形式（テキスト／画像 1 枚／カルーセル）・リンクを入れて「下書きを作る」
2. **構成**: Codex が下書きを作る（30 秒ほど）。「冒頭をもっと具体的に」のように頼むと直してくれる。本文は自分でも直して「下書きを保存」できる
3. **画像**（画像を使うときだけ）: まだ無い画像をまとめて作る。気に入らない 1 枚だけ作り直せる（1 枚 1〜3 分）
4. **仕上げ**: Threads に出る形（本文・トピックタグ・画像・自分への返信）と、文字数・リンク数の検査結果を確かめる。本文・返信はコピーボタンで手でも投稿できる
5. **パソコンに保存する（投稿パッケージ）**: 完成した下書きを `~/Desktop/Threads投稿/<日時>_<テーマ>_<ID>/` に保存する。「フォルダを開く」「ZIP でダウンロード」もできる

下書きは「下書きの一覧」からいつでも開き直せる（「消す」で削除。保存したパッケージのフォルダは残る）。画面を閉じても、生成は最後まで続く。画像は「この 1 枚だけ作り直す」ができ、前に作った版を選び直すこともできる。

### 自分の写真に文字を入れる

基本情報で「自分の写真に文字を入れて投稿する」を選び、写真を 1〜10 枚選ぶ（JPEG・PNG・HEIC・WebP、1 枚 25MB まで。1 枚なら画像 1 枚、2 枚以上ならカルーセル）。

- **写真は AI で描き直さない**。文字（見出し・補足）だけを、このパソコンの中で写真の上に重ねる（ヒラギノ角ゴシック）。AI が加工した写実的な画像に付く「AI info」ラベルの対象にならない
- Codex は写真を見て、写真に合う見出し・補足・本文・代替テキストを書く。写っていないことは書かない
- 取り込むときに、向きを直し、**位置情報（GPS）などのメタデータを消し**、長い辺を 2560px までにした JPEG だけを保存する（元のファイルは保存しない）
- 画像の段で、写真ごとに「文字の置き場所（下・上・真ん中・なし）」「色（黒地・白地）」「切り抜き（真ん中・上・下を残す）」を変えられ、すぐ入れ直される
- 文字が多すぎて写真に収まらないときは、その写真だけ理由を表示する（見出しか補足を短くする）

### 投稿パッケージの中身（すべてこのパソコンの中。インターネットには送らない）

| ファイル | 中身 |
|---|---|
| `本文.txt` | 投稿する本文（フリー版のクレジット・本文に付けるリンクを含む、送るそのままの形） |
| `返信.txt` | 自分への返信（あるときだけ） |
| `画像/01.jpg …` | Threads に送れる形に整えた画像（JPEG・sRGB・幅 1440px 以下・8MB 未満） |
| `投稿情報.json` | 形式・トピックタグ・返信できる人・画像の代替テキスト・内容のハッシュ（次の段階の投稿機能がこれを使う） |
| `手動で投稿するとき.txt` | Threads アプリで手で投稿するときの手順 |

保存先は `THREADSPOST_EXPORT_DIR` で変えられる。同じ下書きを保存し直すと、同じフォルダが今の内容に更新される。

## 使い方（無人実行・下書きまで）

```bash
node scripts/auto-post.mjs                                   # ops/themes.txt からテーマを選んで下書きを 1 本作り、投稿パッケージも保存
node scripts/auto-post.mjs --theme="議事録を AI で" --kind=text
node scripts/auto-post.mjs --kind=carousel --slides=3 --jitter=20   # 0〜20 分ずらして開始
```

| 終了コード | 意味 |
|---|---|
| 0 | 下書きを作り、投稿パッケージを保存した |
| 1 | 失敗（会員限定・生成の失敗など。macOS の通知と、画面で見られる記録が残る） |
| 2 | 未対応（`--publish` は第一段階の後半で対応） |
| 11 | 人の確認が要る（テーマの使い切り・同じ内容の繰り返し・頼んだ形式と違う・決まり違反・保存の失敗） |

- テーマは直近 20 本と被らないものを選ぶ。使い切ったら止まるので `ops/themes.txt` に足す
- 形式はテキスト中心。会員なら 4 回に 1 回だけ画像にする
- 最近の下書きと同じ・書き出しが同じ・よく似ている（文字 3-gram の一致度 0.5 以上・暫定）ときは 1 回だけ作り直す

## 安全のしくみ

- **Codex の隔離**: 生成 1 回ごとに専用のプロセスで動かす。普段の `~/.codex/config.toml`（MCP・プラグイン）は読まない（`--ignore-user-config`）。書き込めるのはその生成の作業フォルダだけで、`/tmp` も書けない。ネットワークも切る。環境変数は必要なものだけ渡す
- **取り込み**: Codex が作った画像は、通常のファイル・PNG・作業フォルダの中、を確かめてから管理領域（`~/.threadspost-data/jobs/`）に写す。時間切れや中断した生成の出力は使わない
- **画面の API**: この Mac（127.0.0.1）からだけ受け付け、起動ごとの鍵（Cookie とヘッダー）を確かめる。ほかのサイトからの要求は断る
- **状態の記録**: SQLite（`~/.threadspost-data/state.db`）。同じ下書きの生成は同時に 1 つだけ

### 残るリスク（正直に書いておくこと）

- 同じ OS ユーザーで動く Codex が、ホーム配下のファイルを**読む**ことは技術的に止められない（codex 0.160 のサンドボックスは書き込み先しか制限できない）。2026-10-02 の確認では、サンドボックスの中からキーチェーンは読めなかった
- Threads のトークンは第一段階の後半で扱う（キーチェーンに保存し、ファイル・環境変数・プロンプトには置かない予定）

## データの置き場

| 場所 | 中身 |
|---|---|
| `~/.threadspost-data/state.db` | 下書き・会話・画像の版・生成の記録・知らせ |
| `~/.threadspost-data/jobs/<id>/images/` | 取り込んだ画像・文字を重ねた画像（書き換えない） |
| `~/.threadspost-data/jobs/<id>/photos/` | 取り込んだ写真（メタデータを消した JPEG） |
| `~/.threadspost-data/work/<id>/gen-*/` | Codex の作業フォルダ（使い終わったら消してよい） |
| `~/Desktop/Threads投稿/` | 投稿パッケージ（利用者のファイル。下書きを消しても残る） |

`THREADSPOST_DATA_ROOT` で場所を変えられる（一時フォルダの下は不可）。

## 投稿の中身を変えたいとき

`public/docs/brand.md`（キャラ・CTA）と `public/docs/threads-format.md`（Threads の作法）を書き換える。画面と無人実行の両方に効き、ビルドし直す必要はない。
